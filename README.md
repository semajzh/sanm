# sanm

三国武将 3V3 回合制模拟战斗程序（C++ / Qt）。

本文档分三部分：**一、需求与实现对照**（按功能模块，需求描述紧跟对应代码实现，便于查阅）；**二、代码结构速查**（按文件/目录列出，用于快速定位）；**三、附录**（ID 对照表、状态描述表，供后续逐条填写"描述"列）。

---

## 一、需求与实现对照

### 1. 战斗总览

**需求**：两支队伍，蓝方和红方，每支队伍选用一个阵型，阵型有三个位置，可以上阵三个武将，武将持有战法、韬略、装备，有不同的兵种。

**实现**：`Group` 配置队伍（阵型 + 三名武将）；`Item` 为武将类；`Ground` 持有整场战斗（蓝红两个 `Group`）的全部信息。

### 2. 回合流程与状态机

**需求**：战斗采用回合制，两支队伍六名武将按照先攻（速度）顺序依次行动。整场战斗分为几个阶段：组队阶段、战斗准备阶段、战斗阶段、战斗结束阶段；战斗阶段最多八个回合（或一方全灭回合结束），每个回合又分为几个子阶段：回合开始、回合中、回合结束；回合中，六名武将按先攻顺序行动，每个武将行动时又分为几个子阶段：武将行动开始、武将发动主动战法、武将发动普通攻击、武将发动追击战法、武将行动结束。武将间互相攻击造成伤害，减少对方兵力，兵力为 0 时阵亡。

**实现**：

- `Dispatcher`：整个进程唯一的额外线程，驱动状态机（`STATE`）运转。
- `state` 目录：状态机系列类，共四层。
  - 第一层：`state1`（加载队伍）、`state2`（战斗开始）、`state3`（战斗结束，输出战报）、`idle`。
  - 第二层（`state2` 的子状态）：`state21`（准备阶段）、`state22`（战斗阶段）。
  - 第三层（`state22` 的子状态）：`state221`（回合开始阶段）、`state222`（回合进行中阶段）、`state223`（回合结束阶段）。
  - 第四层（`state222` 的子状态）：`state2221`（武将行动开始）、`state2222`（武将发动主动战法）、`state2223`（武将发动普通攻击）、`state2224`（武将发动追击战法）、`state2225`（武将行动结束）。
- `ground.h`/`ground.cpp`：战场类，持有战场上的全部信息。
  - 成员变量：`m_round`（回合数）、`m_group`（两支队伍的对象）、`m_sort`（每回合开始的行动顺序）、`target2223`（每回合内的普攻目标）、`data`（每个武将的战斗统计数据：`act` 伤害数据、`actcount` 伤害次数、`hlo` 治疗数据、`hlocount` 治疗次数、`h0` 每回合结束时的兵力、`acted` 受到的伤害总数、`actedcount` 受到的伤害总次数、`round` 死亡的回合数、`actrc` 姜维九伐中原的次数）、`buff`（状态列表，详见"三、附录 § 状态设计"）、`exceptions`（异常状态列表）。
  - 成员方法：`isover`（判断战斗是否结束，某支队伍全员阵亡）、`getMaxi`（获取某武将武力/智力/统率/先攻的最高属性值）、`selectObjN`（选将，见下方 criteria 说明）、`actbr`（造成兵刃伤害）、`actml`（造成谋略伤害）、`acttb`（造成逃兵伤害）、`actcd`（造成传递伤害）、`hlo`（治疗）、`exenter`/`exexit`/`exupdate`/`exremove`（负面状态的施加/消失/刷新/移除）。

**`selectObjN` 的 `criteria` 位定义**（2 字节，0xFFFF）：

| 位段 | 含义 |
| --- | --- |
| 0xF000 | 选择武将属性：0x1000 武力最高 / 0x2000 武力最低 / 0x3000 智力最高 / 0x4000 智力最低 / 0x5000 统率最高 / 0x6000 统率最低 / 0x7000 先攻最高 / 0x8000 先攻最低 / 0x9000 兵力最高 / 0xA000 兵力最低 |
| 0x0F00 | 选择武将位置：0x0100 前排 / 0x0200 后排 |
| 0x00F0 | 选择武将队伍：0x0010 队友 / 0x0020 敌人 / 0x0030 队友（混乱状态下改为全部武将）/ 0x0040 敌人（混乱状态下改为全部武将） |
| 0x000F | 选择人数：0x0001~0x0006（1~6 人） |

注意：`selectObjN` 内部实现中，一旦 `0xF000`（属性最高/最低）位非 0，函数会直接按该属性筛出唯一一人后 `return`，`0x0F00`（前后排）与`0x000F`（人数）两个位段会被忽略（此时人数固定为 1）。例如 `0x5010` 实际就是"选统率最高的 1 名队友"，末位的 `0` 并不代表"0 人"。

#### 2.1 战斗准备阶段（`State21`）详细流程

`State21::run` 按固定顺序依次执行：

0. **`prepare`**：把 50 点自由属性点（`i4~i7`）加到当前属性（`i0~i3`）上，并把此时的 `i0~i3` 快照进 `i8~i11`。**`i8~i11`（"基础值"）就是在这一步、其余所有加成（阵型/阵营/星级/兵种/科技/缘分/韬略）介入之前锁定的数值**。
1. **`formation`**：解析阵型（站位、受击率、阵型属性加成）。
2. **`faction`**：解析阵营加成——同阵营 3 人，全属性（武智统先）×(1+10%)；同阵营 2 人，×(1+5%)；三人分属不同阵营则无加成。
3. **`star`**：星级加成——每一星 `k[0]`（增伤）+1（星级>0 时再加一个 0~4 的随机值），`l[0]`（减伤）-1（即每星约 1% 增减伤）。
4. **`kind`**：兵种加成（同兵种数量羁绊），2/3 人同兵种时的效果如下：

   | 兵种 | 2 名同兵种 | 3 名同兵种 |
   | --- | --- | --- |
   | 弓兵 | 造成伤害 +3.5% | 造成伤害 +5% |
   | 盾兵 | 受到伤害 −3.5% | 受到伤害 −5% |
   | 骑兵 | 造成伤害 +1.4%，受到伤害 −2.1% | 造成伤害 +2%，受到伤害 −3% |
   | 枪兵 | 造成伤害 +2.1%，受到伤害 −1.4% | 造成伤害 +3%，受到伤害 −2% |

5. **`technology`**：科技加成——全属性（`i0~i3`）各 +20，`k[0]` +10，`l[0]` −10。
6. **`relation`**：遍历缘分 ID 100~599，逐个判定并结算（见"三、附录 § 3 缘分对照表"）。
7. **`strategy`**：逐个武将，按其佩戴的韬略结算（见"三、附录 § 2 韬略对照表"）。
8. **`speed`**：出手顺序——当前实现是直接按先攻（`i[3]`）从高到低排序（简化实现）。官方设定里先攻差距会影响"优先行动概率"，差距超过 70 时必定优先，这部分暂未实现，是已知的简化点。
9. **`method`**：按 8 步排好的顺序，依次处理每个武将佩戴的战法中类型为被动（`type%100==20`）和指挥（`type%100==21`）的部分（先被动、同一武将内后指挥）；主动、追击战法在正式回合中（`state2222`/`state2224`）另行处理。

### 3. 兵力与伤亡

**需求**：初始 10000，受到伤害后 1/5 阵亡变成死兵，4/5 变成伤兵，伤兵可以被治疗，死兵不可以被治疗。

**实现**：`Item::h[]` 数组，`h[0]` 当前兵力、`h[3]` 兵力上限（初始均为 10000）、`h[1]` 伤兵、`h[2]` 死兵（`ground.cpp` 中 `h[1] += p - p/5; h[2] += p/5;`）。

### 4. 兵种克制

**需求**：弓、盾、骑、枪，有克制关系，盾兵克弓兵、弓兵克枪兵、枪兵克骑兵、骑兵克盾兵，克制时造成的伤害提高 15%，被克制时造成的伤害降低 15%。

**实现**：`Item::g[4]`（兵种：0 弓 1 盾 2 骑 3 枪），克制加成在 `ground.cpp` 的 `actbr` 中按兵种差值计算（±15%）。

### 5. 伤害类型与计算公式

**需求**：伤害类型包括兵刃伤害（物理）、谋略伤害（法术）、逃兵伤害（真伤）、传递伤害（A 受到伤害后，其队友受到固定比例的伤害）。

**实现**：`Ground::actbr`（兵刃）、`actml`（谋略）、`acttb`（逃兵）、`actcd`（传递）。

**伤害计算公式**：

```
兵刃伤害 = Scale(0.283) × 技能系数 × √兵力 × 武力 / √(统率 + 55)
           × (1+增伤) × (1−减伤1) × (1−减伤2) × ... × (1−减伤n)
           × [会心时](1+会心伤害) × 兵种克制增伤(15%)

谋略伤害 = Scale(0.283) × 技能系数 × √兵力 × 智力 / √((智力 + 统率) / 2 + 55)
           × (1+增伤) × (1−减伤1) × (1−减伤2) × ... × (1−减伤n)
           × [奇谋时](1+奇谋伤害) × 兵种克制增伤(15%)
```

其中，公式里的"武力/智力/统率"均为**目标**（受击方）的对应属性（分别受攻击方的破甲率、看破率影响削减）；"武力/智力"为攻击方数值。

**治疗计算公式**：

```
治疗量 = (0.930094206017815 + 0.0055332101979583 × 兵力^0.274780014559044)
         × 治疗系数
         × (0.00257413709518457 × 智力² + 0.0558280362334805 × 智力 + 117.637581883191)
```

### 7. 普攻与反击

**需求**：普通攻击，在普通攻击阶段 100% 发动，正常一个回合只能发动一次，但连击判定成功后可额外发动一次，连击只能多发动一次普通，其他战法可能发动多次普攻。反击是一种强力的普攻，在受到对方普通攻击时有一定几率反击，反击每回合最多发动 5 次。

**实现**：`state2223`（武将发动普通攻击阶段）；`Ground::run2223`/`run3332`（普攻/反击流程）。

### 8. 战法

**需求**：包括指挥（战斗准备阶段发动）、被动（战斗准备阶段发动）、主动（武将行动主动阶段发动）、追击（普通攻击成功之后发动）几种类型。每个武将佩戴三个战法，武将自带一个战法，可任选两个其他战法。指挥战法和被动战法 100% 发动，主动战法和追击战法有一定的基础发动几率，主动战法分为普通主动战法和准备战法，准备战法首次发动时（也需要判定发动率）不触发战法效果，下一个回合行动时（无需判定发动率）触发战法效果。

**实现**：`method` 目录（战法类，一个战法一个子类，文件名即战法 ID）；`base/method20.h`、`method21.h`、`method22.h`、`method24.h`、`method27.h`（各类型战法的模板/基类，`method22.h` 对应示例 id=9999999 的占位类）。ID 设计见"三、附录 § ID 设计"；战法名称/ID 对照见"三、附录 § 1 战法对照表"。

### 9. 韬略

**需求**：在战斗准备阶段发动，每个武将佩戴三个韬略，武将可以佩戴自身的金韬略和另外两个通用韬略，也可以佩戴三个通用韬略。

**实现**：`strategy` 目录（韬略类，一个韬略一个子类，文件名即韬略 ID）。ID 设计见"三、附录 § ID 设计"；韬略名称/ID 对照见"三、附录 § 2 韬略对照表"。

### 11. 阵型

**需求**：站位分前排和后排，各有不同的受击率（被战法选中的几率），还有一些属性加成效果。共八种阵型：

| 阵型 | 站位（前/后） | 效果 |
| --- | --- | --- |
| 一字阵 | 前33% / 前34% / 前33% | 所有武将受到的伤害降低 8% |
| 箕形阵 | 前60% / 后20% / 后20% | 前排受到的伤害降低 6%，后排造成的伤害提高 12% |
| 雁形阵 | 后20% / 前40% / 前40% | 前排造成的伤害提高 15%，后排统率提高 20 |
| 方圆阵 | 前40% / 前40% / 后20% | 前排受到的伤害减少 5%，后排连击率增加 40% |
| 锥形阵 | 后20% / 前60% / 后20% | 前排造成的伤害增加 16%，后排受到的伤害减少 5% |
| 鱼鳞阵 | 前60% / 后20% / 后20% | 前排闪避率增加 12%，后排会心/奇谋率增加 8% |
| 钩形阵 | 后20% / 后20% / 前60% | 后排连击率增加 25%，前排受到的伤害减少 8% |
| 偃月阵 | 前40% / 后20% / 前40% | 前排造成的伤害增加 14%，后排受到的伤害减少 5% |

**实现**：`group.h`/`group.cpp`（配置队伍与阵型）；`Item::g[2]`/`g[3]`（最大/最小受击率）。

### 12. 星级

**需求**：0~5 星，武将和战法都有星级，武将每多一个星级增加 10 点自由属性点，最多 5 星 50 个自由属性点；武将每多一个星级，自带战法的数值会增加（具体增加规律参考代码），战法的星级效果也一样。

**实现**：`Ground::pointbystar`（战法/韬略数值的星级成长）；`State21::star`（武将星级带来的通用增减伤，见"2.1 战斗准备阶段详细流程"：每星 `k[0]`+1、`l[0]`-1，约合每星 1% 增减伤，`k[0]` 在星级>0 时还额外 +0~4 的随机值）。

### 14. 状态

**需求**：包括增益状态和负面状态。

- 增益状态分为常规增益状态（会心、奇谋、破甲、看破、倒戈、攻心、连击、反击、规避，以及某些战法产生的增益，包括但不限于造成伤害提升、受到伤害降低、属性提升等）、功能性增益状态（清醒、抵御、必中、破御、伏兵，以及某些战法产生的功能性增益，包括但不限于布阵、整备、列阵等）。
- 负面状态分为异常状态（非控制状态：洪水、火攻、风暴、畏惧、妖术；控制状态：震慑、缴械、技穷、混乱、嘲讽、虚弱、断粮）、常规负面状态（焚烧、鸩毒，以及某些战法产生的负面，包括但不限于造成伤害降低、受到伤害提升、属性降低等）。

具体状态描述详见"三、附录 § 4 增益状态描述"、"§ 5 负面状态描述"。

**实现**：`buff` 目录（状态类，一个状态一个子类）；`Ground::buff[10]`（按生命周期分为 9 种，另有 1 组预留，详见下表）；`Ground::exceptions`（异常状态列表）。

### § 4 增益状态描述

| 状态 | 类别 | 效果 |
| --- | --- | --- |
| 会心 | 常规 | 造成兵刃伤害时，有概率使本次伤害提升 50%（会心伤害） |
| 奇谋 | 常规 | 造成谋略伤害时，有概率使本次谋略伤害提升 50%（奇谋伤害） |
| 破甲 | 常规 | 造成兵刃伤害时，无视目标部分统率 |
| 看破 | 常规 | 造成谋略伤害时，无视目标部分智力 |
| 倒戈 | 常规 | 造成兵刃伤害时，根据伤害恢复自身兵力（物理吸血） |
| 攻心 | 常规 | 造成谋略伤害时，根据伤害恢复自身兵力（法术吸血） |
| 连击 | 常规 | 可额外进行 1 次普通攻击 |
| 反击 | 常规 | 受到普通攻击后，有概率对攻击方进行 1 次强力普通攻击；不触发追击战法，每回合最多反击 5 次，反击本身受普通攻击伤害加成影响 |
| 规避 | 常规 | 受到伤害时，有概率使该次伤害无效 |
| 清醒 | 功能性 | 使受到的控制状态暂时失去作用（清醒结束后，原控制状态继续发挥剩余作用，而非被清除） |
| 抵御 | 功能性 | 最多持有 2 层；受到伤害时，消耗 1 层使该次伤害降低 70%~90% |
| 必中 | 功能性 | 造成的伤害无法被规避 |
| 破御 | 功能性 | 造成的伤害无法被抵御 |
| 伏兵 | 功能性 | 受到伤害时，消耗伏兵抵挡部分伤害，并对伤害来源造成「逃兵」 |
| 不屈 | 功能性 | 周泰战法效果（非通用状态词条），免疫 1 次致命伤害 |

### § 5 负面状态描述

| 状态 | 类别 | 效果 |
| --- | --- | --- |
| 震慑 | 控制 | 无法发动主动战法和普通攻击（本回合被跳过），但已生效的准备阶段效果依然可以造成伤害 |
| 缴械 | 控制 | 无法普通攻击 → 连带无法触发追击、连击 |
| 技穷 | 控制 | 无法发动主动战法 |
| 混乱 | 控制 | 普通攻击、追击战法和主动战法无差别选择目标（可能误伤友军）；对指挥、被动战法无效 |
| 嘲讽 | 控制 | 强制普通攻击嘲讽施加者 |
| 虚弱 | 控制 | 造成的最终伤害降低 70% |
| 断粮 | 控制 | 受到的恢复兵力效果降低 70% |
| 洪水 | 非控制 | 统率降低 20 点 |

| 妖术 | 非控制 | 会心和奇谋伤害降低 15% |
| 焚烧 | 常规负面 | 每回合受到 60% × 层数 的谋略伤害，最多叠加 5 层（满层每回合 300% 谋略伤害） |
| 鸩毒 | 常规负面 | 每回合受到 60% × 层数 的谋略伤害，最多叠加 5 层，机制与焚烧相同 |
